### Лабораторна робота №7 
## Тема: Узагальнені типи (Generics). IRepository з where-обмеженнями та тестами.
## Мета: Навчитися створювати узагальнені інтерфейси та класи, застосовувати where-обмеження для типів-параметрів, а також розробляти юніт-тести для перевірки коректності узагальнених реалізацій. 
## Висновок
Під час виконання лабораторної роботи я опанувала практичні навички роботи з узагальненими типами (Generics) у C#. Створила інтерфейс IEntity та клас User за 2-м варіантом, а також узагальнений репозиторій InMemoryRepository<T> із where-обмеженням для реалізації CRUD-операцій у пам'яті. Для перевірки коректності роботи репозиторію розробила юніт-тести за допомогою фреймворку xUnit, які успішно пройшли перевірку.

## відповіді на питання
1. Яка роль where-обмежень у Generics? Наведіть приклади їх використання.

Обмеження where гарантують, що тип-параметр T має певні властивості (реалізує інтерфейс, успадковує клас, має конструктор за замовчуванням тощо). Це дозволяє безпечно звертатися до методів і властивостей типу T усередині узагальненого класу.
• where T : class: T має бути посилальним типом.
• where T : struct: T має бути типом-значенням (не nullable).
• where T : new(): T має мати публічний конструктор без параметрів.

2. Навіщо потрібен шаблон IRepository? Які переваги він дає?

Абстрагувати джерело даних (база даних, пам'ять, REST API) від бізнес-логіки додатка. 
Переваги: Повторне використання CRUD-операцій. Легкість тестування. Зниження зв'язаності коду.

3. Поясніть, чому юніт-тести є важливими при розробці узагальнених компонентів.

Юніт-тести дозволяють переконатися, що логіка працює стабільно та передбачувано незалежно від конкретної реалізації сутності.

4. Які проблеми вирішують Generics порівняно з використанням object?

Безпека типів : Помилки невідповідності типів виявляються на етапі компіляції, а не під час виконання.
Продуктивність: Відсутність операцій пакування/розпакування для значущих типів.
Чистота коду: Зникає потреба в постійному явному приведенні типів.
