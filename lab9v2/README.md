# Висновок
У ході лабораторної роботи я практично виконала роботи з колекціями в C#. Зрозуміла, що HashSet<T> підходить для неупорядкованих, унікальних елементів та фільтрації дублікатів. Queue<T> використовується для черг завдань та обробки подій. А Stack<T> використовується для відміни операцій, обходу дерев та обробки рекурсивних структур.
# Відповіді на питання
1. У чому різниця між List<T> та HashSet<T>?   List<T> зберігає елементи послідовно в порядку додавання, може містити дублікати, а пошук виконується за O(n). HashSet<T> зберігає тільки унікальні елементи, порядок не гарантується, але пошук через хеш-таблицю відбувається дуже швидко — за O(1).   
2. Коли доцільно використовувати Queue<T> замість List<T>?   Коли треба обробляти дані за принципом «хто перший прийшов — той перший оброблений» (FIFO). У Queue<T> операції додавання в кінець (Enqueue) і вилучення з початку (Dequeue) працюють за O(1), тоді як видалення з початку у List<T> змушує зсувати всі елементи (O(n)).   
3. Наведіть приклад реальної задачі, де потрібен Stack<T>.   Найпростіший приклад — кнопка «Назад» у веб-браузері або функція скасування дії (Ctrl+Z / Undo) в текстовому редакторі, де останній здійснений крок скасовується першим.
4. Яка складність операції Contains() для HashSet<T> і чому?   У середньому O(1). HashSet<T> шукає елемент не перебором, а за його хеш-кодом (GetHashCode), що дозволяє одразу вирахувати потрібну комірку в пам'яті.   
5. Чому Queue<T> називають FIFO, а Stack<T> — LIFO?   FIFO (First In, First Out) — першим виходить той елемент, який зайшов першим (як у звичайній черзі в магазині).   LIFO (Last In, First Out) — першим виходить той елемент, який зайшов останнім (як у стопці тарілок: верхню поклали останньою, але забираємо її першою).
