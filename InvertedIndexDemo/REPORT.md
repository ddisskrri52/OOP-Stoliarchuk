# Звіт до самостійної роботи №16

## Мета роботи
Розробити власну реалізацію інвертованого індексу для повнотекстового пошуку та порівняти продуктивність різних підходів до пошуку в колекціях.
# Результат
| Кількість документів | Лінійний пошук (ticks) | Inverted Index (ticks) | Знайдено документів |
|----------------------|------------------------|------------------------|---------------------|
| 10                   | 180533                 | 22636                  | 10                  |
| 1000                 | 72634                  | 1024                   | 1000                |
## Висновки
У цій роботі я закріпила на практиці використання колекцій, створивши власний Inverted Index. Під час масштабування до 1000 документів інвертований індекс демонструє колосальну перевагу (1024 тіки проти 72634), знаходячи результати за O(1). Лінійний пошук деградує пропорційно зростанню обсягу даних O(n). Отже, створення інвертованого індексу є абсолютно виправданим для систем з великими обсягами текстів.
## Відповіді на контрольні запитання
1. Чому структура Dictionary<string, HashSet<int>> добре підходить для реалізації інвертованого індексу?
Словник (Dictionary) забезпечує пошук слова за час O(1), що значно швидше за лінійний перебір. Значенням є HashSet<int>, що гарантує унікальність ID документів та дозволяє швидко виконувати операції над множинами.

2. Які переваги HashSet<T> дає під час обчислення AND/OR-пошуку за кількома словами?
Він має оптимізовані вбудовані методи для операцій з множинами: IntersectWith (перетин) для логічного AND та UnionWith (об'єднання) для логічного OR.

3. Чому під час вимірювання продуктивності важливо однаково нормалізувати текст для лінійного пошуку та пошуку через індекс?
Це необхідно для коректного порівняння, щоб обидва алгоритми виконували пошук за однаковими правилами і знаходили однакову кількість збігів (наприклад, ігнорували регістр та пунктуацію).

4. Які обмеження має проста реалізація інвертованого індексу без ранжування, стемінгу та підтримки фраз?
Вона не здатна шукати точні словосполучення, не розуміє форми слова (наприклад, program і programming сприймаються як різні слова) та не сортує результати за релевантністю.
