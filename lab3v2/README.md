Лабораторна робота №3
  
• Тема: Життєвий цикл об’єкта та керування ресурсами. 

Мета: Поглибити розуміння життєвого циклу об’єкта в C#, навчитися працювати з некерованими ресурсами, реалізувати інтерфейс IDisposable та патерн Dispose. 

Висновки

Під час виконання лабораторної роботи №3 я поглибила знання щодо життєвого циклу об’єктів у C# та керування ресурсами.
На практиці реалізувала клас DatabaseConnection із застосуванням патерну Dispose для безпечного звільнення керованих і некерованих ресурсів.
Також опанувала використання конструкції using для автоматичного виклику Dispose() та дослідила взаємодію з Garbage Collector через деструктор ~DatabaseConnection() і метод GC.SuppressFinalize(this).

Контрольні запитання та відповіді

У чому різниця між керованими та некерованими ресурсами?
Керовані ресурси — це пам'ять, яка виділяється для об'єктів .NET і повністю контролюється збирачем сміття (Garbage Collector).
Некеровані ресурси — це ресурси операційної системи (файлові дескриптори, мережеві сокети, з'єднання з БД), про які GC «не знає» і які потребують явного закриття розробником.

Для чого призначений інтерфейс IDisposable та метод Dispose()? 
Інтерфейс IDisposable надає стандартний механізм для детермінованого звільнення некерованих ресурсів. 
Метод Dispose() викликається розробником або конструкцією using одразу, коли об'єкт більше не потрібен.

Як працює оператор using у C#? Оператор using є синтаксичним цукром для блоку try...finally.
Він гарантує, що метод Dispose() буде викликано для об'єкта при виході з блоку using, навіть якщо всередині виникла помилка.

Яка роль деструктора (фіналізатора) та для чого потрібен метод GC.SuppressFinalize(this)?
Деструктор (~ClassName()) викликається збирачем сміття перед видаленням об'єкта з пам'яті як «останній шанс» звільнити ресурси, якщо розробник забув викликати Dispose().
Метод GC.SuppressFinalize(this) повідомляє збирачу сміття, що ресурси вже звільнені вручну, і викликати деструктор більше не потрібно, що оптимізує продуктивність.
